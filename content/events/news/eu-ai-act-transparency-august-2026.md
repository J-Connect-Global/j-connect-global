# EU AI Actの透明性義務が2026年8月2日適用｜企業・発信者は何を表示する？

EU AI Act（EU人工知能規則）第50条の透明性義務が、2026年8月2日から適用されています。利用者が「人と話しているのか」「画像・音声・動画・文章がAIで生成または改変されたのか」を、必要な場面で判断できるようにするルールです。

影響を受けるのは大手AI企業だけではありません。WebサイトにAIチャットを置く会社、生成画像を広告に使う店舗、AI音声で案内動画を作る団体、制度・社会問題を扱う記事をAIで作成するメディアも、自社の立場と公開方法を確認する必要があります。

ただし、**AIを少し使った全コンテンツへ同じラベルを貼る制度ではありません。** AIシステムを市場へ出すProviderと、業務で使うDeployerでは義務が異なり、対話、感情認識、生成コンテンツ、ディープフェイク、公益情報テキストでも判定が分かれます。

## 最初に押さえる結論

- 2026年8月2日から第50条が適用
- AIとの直接対話では、原則として相手がAIだと知らせる
- 生成・改変コンテンツの機械可読なマーキングは主にProvider側の設計義務
- ディープフェイクや公益情報を目的とする一定のAI生成テキストは、Deployer側にも人向け開示が関係
- 2026年8月2日より前に市場投入されたAIシステムには、第50条2項のマーキング・検出義務だけ2026年12月2日までの限定的猶予がある
- 8月2日より前に作成されたコンテンツを一律に遡って表示し直す義務はないと欧州委員会Q&Aは説明
- 人の編集・確認があるだけで自動的に例外になるわけではなく、編集管理と責任の実態を確認する

## 四つの義務を混ぜない

| 類型 | 主な場面 | 担当者が確認すること |
| --- | --- | --- |
| AIとの対話 | チャットボット、音声ボット | 利用者がAIだと理解できる時点・場所で通知されるか |
| 感情認識・生体分類 | 顧客・従業員等の状態分析 | 対象者への通知、他の禁止・高リスク規制、個人情報法 |
| 機械可読マーキング | AI生成・改変した画像・音声・動画・文章 | Providerが検出可能な形式を組み込み、後工程で保持できるか |
| 人向け開示 | ディープフェイク、公益情報目的の一定テキスト | 見る人に分かる表示、表示位置、例外条件、編集責任 |

「透かしを入れたからチャット通知は不要」「キャプションを書いたからファイルの由来情報は消してよい」という関係ではありません。人向け表示と機械向け情報は目的が異なり、両方が関係するケースがあります。

## ProviderとDeployerを実務で見分ける

- **Provider（提供者）**：AIシステムを開発し、自社名・商標でEU市場へ提供または運用開始する主体
- **Deployer（導入・利用者）**：自社の権限の下でAIシステムを職業上使用する主体
- **利用者・対象者**：AIとやり取りする人、分析される人、生成物を見る人

たとえば、外部の生成AIサービスで店舗のSNS画像を作る場合、店舗は通常Deployer側の検討が中心です。外部AIを組み込んだ顧客向けサービスを自社名で提供し、目的や構成を大きく変更する場合は、単なる利用者と決めつけず契約・技術構成を確認します。

実務では製品名だけで立場を決めず、次の質問に答えます。

1. 誰の名称・商標で利用者へ提供しているか
2. 誰が用途、プロンプト、データ、出力方法を決めるか
3. AIモデル・システムを改変、再ブランド、再販売しているか
4. 利用者は外部AI事業者と自社のどちらと契約するか
5. 技術的マーキングを誰が生成し、誰が公開工程で保持するか

## ケース1：WebサイトのAIチャット

AIチャットでは、利用者が人と話していると誤解しないよう、遅くとも対話開始時に明確に知らせる設計を確認します。利用規約の奥、フッターだけ、初回だけ一瞬表示される通知では、利用者が実際に理解できるかを検討します。

表示例：

> このチャットはAIが自動応答します。個別契約・医療・法務等の最終判断は担当窓口へ確認してください。

加えて、次を用意すると実務上安全です。

- 人の担当者へ切り替える方法
- 緊急連絡を扱えない旨
- 個人情報・機密情報を入力しない注意
- 応答ログの保存と利用目的
- 誤回答を報告する窓口
- 対応言語と、翻訳の限界

単に「AI」と表示するだけで、データ保護、消費者保護、契約責任が終わるわけではありません。

## ケース2：生成画像・音声・動画

Providerは、AI生成・改変コンテンツを機械で検出できるよう、技術的に有効で相互運用可能、堅牢かつ信頼できるマーキングを出力へ組み込む必要があります。公開者側では、使用ツールが何を付与するかと、編集工程で何が失われるかを確認します。

よくある消失ポイント：

- スクリーンショットで再保存する
- SNSがメタデータを削除する
- 動画編集・音声変換で別形式へ書き出す
- 画像最適化サービスが情報を落とす
- 複数素材を合成し、由来記録が分からなくなる
- 外注先から完成ファイルだけ受け取る

公開前に、原本、使用ツール、生成日、編集内容、最終ファイル、目視ラベルを紐付けて保存します。機械可読情報が残せない媒体では、それで義務がなくなると自己判断せず、Providerの説明と自社の人向け表示を確認します。

## ケース3：ディープフェイク

AIで生成・操作された画像、音声、動画が、既存の人物・物・場所・出来事に似ており、本物・真実と誤認され得る場合は、Deployerによる開示が問題になります。

特に注意する例：

- 経営者が実際には話していないメッセージ動画
- 実在する社員の声を模した研修音声
- 実際に起きていない事故・災害の再現画像
- 実在する会場で撮影したように見えるイベント写真
- 顧客の顔を別の服装・体型へ合成した広告

芸術、風刺、創作等では表示方法に配慮が認められる場合がありますが、作品性を損なわない方法であっても、生成・操作されたことの適切な開示を検討します。

表示例：

> AIで生成した編集イメージです。実在する人物の発言・実際の出来事を記録したものではありません。

「イメージ画像」だけでは、AI生成なのか一般的な写真素材なのか分からないため、誤認リスクに応じて具体化します。

## ケース4：公益情報を伝えるテキスト

公共の利益に関する事項を一般の人へ知らせる目的でAIが生成・操作した文章は、人向け開示が必要となる可能性があります。政治、選挙、法律・制度、災害、健康、治安、経済、教育などは典型的に慎重な判定が必要です。

一方、欧州委員会の説明では、人によるレビューまたは編集管理があり、自然人または法人が編集責任を負う場合の例外があります。ここで重要なのは、**誰かが公開ボタンを押したことではなく、内容を実質的に検証・編集し、組織が責任を負っているか**です。

最低限、次を記録します。

- 主張ごとの公式一次資料
- 数値・日付・適用対象の確認者
- AI出力から削除・修正した箇所
- 見出し・結論を決めた編集者
- 公開承認者と承認日時
- 訂正受付・更新履歴

ニュース記事、制度解説、健康情報では、AIの使用表示だけで誤情報の責任を回避できません。出典の存在、現在性、文脈、例外条件まで人が確認します。

## ケース5：感情認識・生体分類

コールセンターで声から感情を推定する、カメラ映像から顧客属性を分類する、従業員の反応を分析するなどの用途では、対象者への通知だけでなく、AI Actの禁止用途・高リスク用途、GDPR、労働法、共同決定権など別の論点も関係します。

「通知すれば使える」とは限りません。次を法務・データ保護・従業員代表と確認します。

- 何を推定し、どの意思決定に使うか
- 同意以外の法的根拠を含むデータ処理根拠
- 誤判定による不利益と人による再審査
- 保存期間、アクセス権、外部提供
- 使用停止・異議申立ての方法

## 2026年12月2日までの限定的猶予

欧州委員会Q&Aによると、2026年8月2日より前に市場投入されたAIシステムについては、**第50条2項のAI生成・改変コンテンツのマーキング・検出義務に限り**、2026年12月2日までの猶予が想定されています。

これは第50条の全義務が12月まで延期される意味ではありません。AI対話の通知、Deployerの人向け開示などを一括して先送りしないでください。また、8月2日より前に作成されたコンテンツを遡って一律表示し直す義務はないものの、誤認を減らすため可能な範囲で表示することは推奨されています。

| --- | --- | --- |
| マーケティング | SNS画像、広告動画、AIモデル | 人向け表示、素材台帳、外注条件 |
| 広報・編集 | 記事、ニュースレター、声明 | 公式出典、人の編集責任、訂正手順 |

| IT・開発 | 埋込みAI、API、生成機能 | Provider/Deployer、マーキング保持 |
| 調達 | AI SaaS、制作会社、代理店 | 契約上の役割、証跡、再委託、更新 |

## 最低限のAI利用台帳

| 記録項目 | 記載内容 |
| --- | --- |
| Use case ID | 部門横断で重複しない番号 |
| ツール・モデル | 製品名、版、契約主体、提供地域 |
| 目的 | 校正、画像生成、顧客応答、判断支援等 |
| 入力 | 個人情報、機密、著作物の有無 |
| 出力・公開先 | 文章、画像、音声、動画、社内・顧客・一般公開 |
| 自社の立場 | Provider、Deployer、要確認 |
| 第50条類型 | 対話、マーキング、人向け開示等 |
| 人の確認 | 確認項目、担当者、承認権限 |
| 表示 | 画面文言、キャプション、機械可読情報 |
| 証跡 | 原本、プロンプト、編集履歴、承認、保存期限 |
| 再確認日 | ツール更新・用途変更・ガイドライン変更時 |

ツール一覧だけでは不十分です。同じ生成AIでも、社内の文章校正と、顧客向け自動応答、採用候補者の評価では影響が違います。

## 30日で行う実装プラン

### 48時間以内

- 外部公開中のAIチャット、AI人物、音声・動画を洗い出す
- 誤認リスクが高い公開物へ暫定表示を置く
- 新規公開を人の承認なしで自動化している箇所を止める

### 1週間以内

- 部門別台帳を作る
- Provider/Deployerと第50条類型を仮分類する
- 利用中サービスの透明性文書・マーキング仕様を取得する
- 外注先へAI利用・原本・編集履歴を確認する

### 30日以内

- 表示文言と配置をUI・法務・アクセシビリティの観点で統一する
- 公開承認・証跡保存・訂正手順を業務フローへ入れる
- 契約書、制作発注書、SNS運用ルールを更新する
- 担当者へケース演習を行う

## よくある誤解

### 社内メールの文章を整えただけでも表示が必要？

第50条の人向け開示は、すべてのAI補助へ一律に適用されるものではありません。用途、公開先、コンテンツ類型、自社の立場を分けます。ただし、機密情報入力や著作権等の社内ルールは別途必要です。

### AIツールの利用規約に任せればよい？

Providerの機能・義務と、導入企業がどのように利用者へ見せるかは別です。ファイル変換でマーキングを失う、AIチャットを人の担当者のように見せるなど、自社工程で生じる問題は自社で確認します。

### 「AI使用」とフッターへ書けば十分？

表示は、対象コンテンツに接した人が適切な時点で理解できる必要があります。何を指すか分からない包括表示、見えにくい色、小さすぎる文字、音声だけなのに画面外の説明などは見直します。

### 行動規範に署名しないと違反？

行動規範は適合を示す一つの方法ですが、署名しない場合でも他の手段で義務遵守を示す必要があります。署名の有無と、個別利用が適法かどうかを混同しません。

## まとめ

第50条対応は「AI使用」という一言を付ける作業ではありません。**自社の立場、対話か生成物か、機械向けか人向けか、ディープフェイクか公益情報か、人がどのように編集責任を負うか**を分けて判断します。

まず外部公開中の高リスクな利用から棚卸しし、暫定表示、担当者切替、公式出典、人の承認、原本・編集履歴の保存を整えてください。限定的な12月猶予を、全対応の延期と解釈しないことも重要です。

この記事は一般的な情報で、個別サービスへの法的助言ではありません。正式な適用判断はAI Act本文、欧州委員会ガイドライン、各国当局の案内、必要に応じて専門家の助言を確認してください。
