# 公開返信と非公開会話

2026-10-17 実装。GitHub Pagesの公開とApps Scriptの更新は別です。`communityMessagingStatus` が機能対応を返すまで新しい送信フォームは停止し、旧メール転送には戻しません。

## 反映するソース

既存のMaster Apps Scriptプロジェクトで次の3ファイルを同じ内容にします。

1. `apps-script/community-board-api.gs`（既存ファイルを更新）
2. `apps-script/zoho-mail.gs`（既存のメール処理を維持）
3. `apps-script/community-messaging.gs`（追加）

`doGet`、`doPost`、`onOpen`を別途増やさず、既存のScript PropertiesとデプロイURLを維持してください。IDや認証情報をリポジトリ、画面、ログにコピーしません。

エディターで `initializeCommunityMessaging` を実行すると、Master Spreadsheetに次の非公開の管理シートを追加します。既存投稿や求人の列は変更しません。

- Community Replies：公開返信と本人確認・承認の状態
- Community Conversations / Community Participants / Community Messages：会話・当事者・履歴
- Community Access：一度限りの確認リンクのハッシュ
- Community Message Reports / Community Blocks：通報とブロック
- Community Notifications：通知の再試行情報（確認リンクの秘密値は保存しない）

これらのシートを「ウェブに公開」したり、公開用データ同期へ追加したりしないでください。公開JSONには、承認・メール確認済みの返信の明示した公開項目のみを、元の公開質問に入れます。

**Deploy → Manage deployments → Edit → New version** で、既存Webアプリのバージョンを更新します。別のWebアプリを新規作成する必要はありません。既存の5分トリガー `processWaitingCommunityApprovalNotifications` は通知の再試行も実行します。

## 利用の流れ

| 投稿 | 開始 | 続ける方法 |
| --- | --- | --- |
| 質問・相談 | ニックネーム、確認用メール、返信本文、公開への同意を送信 | メール確認後に運営が承認。投稿者も同じ公開返信フォームで返信できる |
| 売買・友達募集など | ニックネーム、確認用メール、最初のメッセージを送信 | 問い合わせ者のメール確認後に投稿者へ専用リンクを通知。各自のリンクからサイト内で何度でも返信 |

アカウント登録・パスワードは不要です。メールを受け取れる本人であることを専用リンクで確認します。通常のメールの「返信」では相手に届きません。通知には相手のアドレスやメッセージ本文を含めません。

専用リンクは1時間有効、一度限り。アクセスの秘密値はURLフラグメントから最初に取り除き、明示的な確認ボタンでPOST交換します。確認後は会話と当事者に紐づく30日有効のセッションを発行し、ブラウザーのsessionStorageに保存します。新しい確認でその当事者の以前のセッションを置き換えます。期限切れ・別端末では同じ会話のページで登録メールに新しいリンクを送れます。メールやセッションはGETクエリ、公開JSON、GitHubへ出しません。

会話ページはnoindexでサイト内検索・サイトマップに入れず、解析・シェアスクリプトを読み込みません。公開返信はHTMLにも出力します。コミュニティ詳細の既存noindex方針は維持しており、今回の実装だけで検索流入が増えたとは評価しません。

## 公開返信の審査

`Community Replies` の対象行を選び、**J-Connect管理 → 選択した公開返信を承認**。確認済みの`pending`が承認対象です。個人情報、誤情報、宣伝、危険なリンクがないか確認します。メール未確認の行は承認できません。承認済みの本文とニックネームはHTMLエスケープして公開し、親の質問が非公開の場合は返信も公開しません。

公開JSONとHTMLの反映には同期とサイト配信の時間がかかります。投稿者には公開質問へのリンクで通知します。返信先を選んで再返信でき、同じメールの投稿者による返信には「投稿者」と表示します。運営は非表示メニュー、返信者は専用ページから自分の返信を非表示にできます。

## 会話の管理と通知

当事者は会話終了、相手のブロック、通報ができます。終了後は両者が送信できません。ブロックは同じメールの組み合わせによる新しい問い合わせも止めます。会話の履歴は終了後も当事者が読めます。親投稿が削除・非表示の場合は会話へのアクセスを停止します。運営は通報IDから非公開の管理シートで調査します。

メール失敗時も受け付けた本文を重複登録しません。通知は非公開のキューに保持し、既存の5分トリガーから間隔を延ばして再試行します。再試行では有効な新しい確認リンクを作ります。すぐ再試行する必要がある場合は、対象通知の`next_attempt_at`を現在以前にしたうえで**会話の通知を再試行**を実行します。メール送信状況の表示が受付成功と配信成功を混同しないことを確認してください。

## 検証と本番確認

自動テスト：`node scripts/test-community-messaging.mjs` と `npm run validate`。CIのブラウザーテストは外部メールを送らず、公開同意・旧API時の停止・明示的な確認・繰り返し返信・再取得・モバイル表示を確認します。

反映後、公開GET `?action=communityMessagingStatus` に `messaging_version: 2026-10-17.1` があることを確認します。認証付き操作はすべてPOSTです。運営が管理する2つのテストメールで、以下を実確認します。

1. 問い合わせ者の確認前には投稿者に通知されない。
2. 両者が別々の専用リンクで開き、2往復以上返信できる。
3. 相手のメールアドレスが画面・通知に出ない。
4. 期限切れリンクの再取得、終了・ブロック・通報が動く。
5. 質問への返信はメール確認だけでは公開されず、承認後に公開される。
6. 一般問い合わせ・求人掲載・既存投稿者管理の動作が維持される。

ロールバック時はサイト側のフォームを停止させてから対応します。旧`submitInquiry`のメール転送を再有効化すると連絡先を相手に渡すため、戻しません。
