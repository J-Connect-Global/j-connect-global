# ページ内の公開返信と非公開会話

2026-10-18。全カテゴリで公開返信と非公開返信を選べます。元のCommunity投稿・Jobs掲載の承認手順は変更せず、返信だけを事前承認不要にします。

## フォームと返信先

投稿詳細ページの末尾に共通フォームを直接表示します。先頭の「公開返信｜非公開返信」はネイティブラジオを2分割ボタンとして表示し、公開を初期選択にします。送信ボタンは「送信する」だけです。選択に応じて説明、公開同意、削除用パスワードを切り替え、入力本文は保持し、同意だけ解除します。

「返信先」は独立した候補付き入力欄です。「元の投稿」、返信番号、または一意なニックネームで選択でき、存在しない・曖昧な候補は送信できません。各コメントの「返信する」は同じフォームまでスクロールして対象を選択し、短い引用と番号・名前を表示してメッセージ欄にフォーカスします。非公開では選んだコメントの作者が宛先になります。実際のメールはクライアントから指定させず、同じ投稿に属する公開返信IDからサーバーで解決します。

返信番号は投稿内の追加順で固定し、削除後も振り直しません。削除済みは本文・名前を公開せず番号と返信関係だけ残します。返信先リンクは元のコメントへ移動して強調します。既存返信も移行時に番号を割り当てます。

## 即時表示と通知

公開返信は公開同意後、メール確認・運営承認を待たず `published` として保存します。サーバーが保存した公開DTOを返し、送信したページに即時追加します。ページを開いたときには最新の返信を読み、静的HTMLの同期待ちをなくします。通常のディレクトリ／投稿本文は従来の公開JSONを使います。初回に許可するGASの読み取りは `communityMessagingStatus` と `communityPublicReplies` だけです。

メールは投稿完了後に非公開の通知キューへ保存し、既存の5分トリガーから順次送信します。投稿完了メールには投稿先・返信番号・ページへのリンク・削除方法を含め、パスワードは送りません。メール送信や静的HTMLの再構築を待たず応答するため、「公開しました。投稿完了メールは順次送信します」と案内します。通知失敗でも投稿を取り消さず再試行します。本文・メール・削除照合値を公開DTOへ出しません。公開本文以外の連絡先は非公開です。

非公開の最初のメッセージも即時保存し、送信した端末にその新しい会話だけのセッションを返します。ブラウザーのsessionStorageに保存して会話ページを開きます。入力メールだけでは既存の会話にアクセスできません。再送はランダムな作成キーを照合し、メールとrequest_idだけでセッションを取り出せない仕様です。入力メールを受け取れることは未確認なので、その一致だけで元の投稿者という表示や会話をまたぐブロック権限を付けません。

両者に専用リンクを通知します。メールリンクは投稿の承認手続きではなく、非公開会話・公開返信管理へのアクセス手段です。1時間・一度限りの秘密値をURLフラグメントで渡し、最初に取り除き、明示ボタンのPOSTで交換します。確認後のセッションは30日有効で、新たなメールリンクの使用時に更新します。通知には相手のメールや会話本文を含めません。入力メールを間違えるとその受信者にリンクが届くため、フォームで送信前の確認を案内します。

## 削除と不正利用対策

公開返信では8〜128文字の削除用パスワードを利用者が設定します。ブラウザーのWeb Cryptoで返信ごとの32バイトsaltとPBKDF2-HMAC-SHA256 600,000回からキーを導出し、HTTPS POSTします。Apps ScriptではScript Propertiesの `CM_DELETION_PEPPER` によるHMACだけを保管し、パスワード・導出キーを保管しません。saltは削除の際に公開チャレンジAPIで取得します。削除の誤試行は返信ごとに制限します。パスワードはHTML・メール・公開JSON・ログ・localStorageに入れません。

各返信の「削除」はその場でパスワード入力欄を開きます。忘れた場合は登録メールへの管理リンクから非表示にできます。非公開会話では認証済みの会話セッションで自分のメッセージだけを非表示にできます。会話終了・会話内ブロック・通報は引き続き利用可能です。会話をまたぐメール単位のブロックは両者がメールで認証した場合だけ適用します。

公開への明示同意、非公開の宛先確認、ハニーポット、入力所要時間・本文長・連投制限、HTMLのテキスト表示、スプレッドシート式のエスケープをサーバーでも実施します。運営による事後非表示・通報の確認は維持します。未確認メールの一致だけで投稿者本人とは表示しません。

## 本番の移行

既存Master Apps Scriptの対応するファイルを更新します。

1. `apps-script/community-board-api.gs` → 既存 `JConnectApiComplete.gs`。最新の承認通知・選択行修正を保持。
2. `apps-script/zoho-mail.gs` → 既存 `ZohoMail.gs`。既存の `/api` 設定を保持。
3. `apps-script/community-messaging.gs` → 同名の既存ファイル。
4. `apps-script/appsscript.json` → 既存設定・4 OAuthスコープを維持。Googleのメールサービスの権限は不要。

Script Propertiesの既存値は変更しません。旧Config.gsの重複ヘルパーを戻さないでください。`initializeCommunityMessaging` は既存の8つの非公開シートのヘッダー末尾に必要な列だけを追加し、番号と内部pepperを準備します。既存行の削除やテーブルの作り直しはしません。未確認・未承認の旧返信を自動で公開しません。

**Deploy → Manage deployments → Edit → New version** で既存Webアプリを更新します。公開状態APIに `messaging_version:2026-10-18.1`、`inline_replies:true`、`instant_publish:true` があることを確認してからサイトを公開します。古いAPIの場合はフォームを停止し、旧メール転送へ戻しません。

非公開シートやScript Propertiesを公開JSONへ追加しません。静的同期は `CM_PUBLIC_DIRTY` を既存5分トリガーで処理し、通常の定期同期も維持します。公開詳細の既存noindex方針を維持し、会話ページには解析・シェアスクリプトを読み込みません。

## 検証

`node scripts/test-community-messaging.mjs`、`npm run validate`、ブラウザーテストで、旧スキーマ移行、全カテゴリの即時公開、固定番号・返信先・削除済み表示、パスワード照合、メール以外の初回セッション、クロス投稿の拒否、セッション隔離、再送の重複防止、通知再試行、モバイル表示を確認します。

本番では最新APIの対応状態、元の公開投稿の取得、認証なしでの会話アクセス拒否、詳細ページのフォームを確認します。運営管理の2つのテスト受信箱での実配信・往復も確認対象ですが、許可なしに既存の投稿者へテスト通知を送りません。

ロールバックではまずフォームを停止し、旧バージョンのGASとサイトに戻します。新規の `published` 返信と追加列は旧コードから見えない場合があるため、旧ヘッダー前提のコードをそのまま使わず互換性を確認してください。旧submitInquiryのメール転送は再有効化しません。
