# ページ内の公開返信と非公開会話

2026-10-18。全カテゴリで公開返信と非公開返信を選べます。元のCommunity投稿・Jobs掲載の承認手順は変更せず、返信だけを事前承認不要にします。

## フォームと返信先

投稿詳細ページの末尾に共通フォームを直接表示します。先頭の「公開返信｜非公開返信」はネイティブラジオを2分割ボタンとして表示し、公開を初期選択にします。送信ボタンは「送信する」だけです。選択に応じて説明、公開同意、削除用パスワードを切り替え、入力本文は保持し、同意だけ解除します。

「返信先」は独立した候補付き入力欄です。「元の投稿」、返信番号、または一意なニックネームで選択でき、存在しない・曖昧な候補は送信できません。各コメントの「返信する」は同じフォームまでスクロールして対象を選択し、短い引用と番号・名前を表示してメッセージ欄にフォーカスします。非公開では選んだコメントの作者が宛先になります。実際のメールはクライアントから指定させず、同じ投稿に属する公開返信IDからサーバーで解決します。

返信番号は投稿内の追加順で固定し、削除後も振り直しません。削除済みは本文・名前を公開せず番号と返信関係だけ残します。返信先リンクは元のコメントへ移動して強調します。既存返信も移行時に番号を割り当てます。

## 即時表示と通知

公開返信は公開同意後、メール確認・運営承認を待たず `published` として保存します。サーバーが保存した公開DTOを返し、送信したページに即時追加します。ページを開いたときには最新の返信を読み、静的HTMLの同期待ちをなくします。通常のディレクトリ／投稿本文は従来の公開JSONを使います。初回に許可するGASの読み取りは `communityMessagingStatus` と `communityPublicReplies` だけです。

メールは投稿完了後に非公開の通知キューへ保存し、既存の5分トリガーから順次送信します。投稿完了メールには投稿先・返信番号・ページへのリンク・削除方法を含め、パスワードは送りません。メール送信や静的HTMLの再構築を待たず応答するため、「公開しました。投稿完了メールは順次送信します」と案内します。通知失敗でも投稿を取り消さず再試行します。本文・メール・削除照合値を公開DTOへ出しません。公開本文以外の連絡先は非公開です。

非公開の最初のメッセージも即時保存し、送信した端末にその新しい会話だけのセッションを返します。ブラウザーのsessionStorageに保存して会話ページを開きます。入力メールだけでは既存の会話にアクセスできません。再送はランダムな作成キーを照合し、メールとrequest_idだけでセッションを取り出せない仕様です。入力メールを受け取れることは未確認なので、その一致だけで元の投稿者という表示や会話をまたぐブロック権限を付けません。

両者に専用リンクを通知します。メールリンクは投稿の承認手続きではなく、非公開会話・公開返信管理へのアクセス手段です。

2026-10-21から、リンクは参加者（公開返信は返信）ごとに1つの恒久的な秘密値です。時間経過では失効せず、同じリンクを何度でも、別の端末・ブラウザーからも開けます。開いても消費されず、他の端末の画面を締め出しません。以前の「1時間・一度限り」のリンクと「30日」のセッションは廃止しました。

- 秘密値は `HMAC-SHA256(CM_ACCESS_PEPPER, 種別・参加者ID・取消しマーカー)` の256ビットです。Script Propertiesの `CM_ACCESS_PEPPER` は初回に自動生成し、変更しません（変更すると送信済みの全リンクが無効になります）。シート・ログ・通知キューには平文も照合値も保存せず、送信時に毎回同じリンクを導出します。再送・通知の再試行も同じリンクです。
- URLフラグメント `#access=` で渡し、ページの最初のスクリプトがURLから取り除いてから、POST本文だけで照合します。フラグメントはサーバー・Referer・ログに送られません。会話ページは `no-referrer` で、解析・広告・シェア用スクリプトを読み込みません。
- 送信直後の端末に返す値もメールのリンクと同じ秘密値です。sessionStorageに保存し、再読み込み後も会話を表示します。
- 「以前のリンクを無効にする」で取消しマーカーを更新すると、その参加者の旧リンク・旧セッション・旧形式リンクがすべて無効になり、新しいリンクを本人の登録メールにだけ送ります。相手のリンクは影響を受けません。会話終了・ブロック後は送信できませんが、履歴は閲覧できます。投稿が削除・非公開になった場合は開けません。
- 2026-10-21以前に送られた旧形式リンク（`Community Access` のハッシュ）は、期限切れ・使用済みでも、取消し前に発行されたものであれば同じ会話に限り開け、新しいリンクに置き換えます。旧セッションも期限なしで受け付けます。
- リンクを開けない場合は原因を説明します。URLの欠落・無効化・一時的なアクセス不具合など、元の投稿が有効な場合は登録メールアドレスへの再送フォームを表示します。元の投稿が削除・非公開の場合は再送フォームを表示せず、再送しても復旧できないことを明示します。再送応答はメールアドレスの一致に関係なく同じで、アドレスと会話IDを知っていても登録メールにしかリンクは届きません。

通知メールには、相手のニックネーム・投稿タイトル・メッセージ本文を記載し、リンクを開かずに読めるようにします（会話を始めた人には、最初のメッセージの控えと会話リンクを送ります。以降の送信の控えは送りません）。リンクの再送・取消し後のメールは「非公開会話のリンク」としてリンクだけを送ります。本文はメール作成時に `Community Messages` から読み、通知キューには保存しません。削除済みのメッセージは記載しません。メールアドレスはどちらのメールにも記載しません。入力メールを間違えるとその受信者に本文とリンクが届くため、フォームで送信前の確認を案内します。

## 削除と不正利用対策

公開返信では8〜128文字の削除用パスワードを利用者が設定します。ブラウザーのWeb Cryptoで返信ごとの32バイトsaltとPBKDF2-HMAC-SHA256 600,000回からキーを導出し、HTTPS POSTします。Apps ScriptではScript Propertiesの `CM_DELETION_PEPPER` によるHMACだけを保管し、パスワード・導出キーを保管しません。saltは削除の際に公開チャレンジAPIで取得します。削除の誤試行は返信ごとに制限します。パスワードはHTML・メール・公開JSON・ログ・localStorageに入れません。

各返信の「削除」はその場でパスワード入力欄を開きます。忘れた場合は登録メールへの管理リンクから非表示にできます。非公開会話では認証済みの会話セッションで自分のメッセージだけを非表示にできます。会話終了・会話内ブロック・通報は引き続き利用可能です。会話をまたぐメール単位のブロックは両者がメールで認証した場合だけ適用します。

公開への明示同意、非公開の宛先確認、ハニーポット、入力所要時間・本文長・連投制限、HTMLのテキスト表示、スプレッドシート式のエスケープをサーバーでも実施します。運営による事後非表示・通報の確認は維持します。未確認メールの一致だけで投稿者本人とは表示しません。

## 本番の移行

既存Master Apps Scriptの対応するファイルを更新します。

1. `apps-script/community-board-api.gs` → 既存 `JConnectApiComplete.gs`。最新の承認通知・選択行修正を保持。
2. `apps-script/zoho-mail.gs` → 既存 `ZohoMail.gs`。既存の `/api` 設定を保持。
3. `apps-script/community-messaging.gs` → 同名の既存ファイル。
4. `apps-script/appsscript.json` → 既存設定・4 OAuthスコープを維持。Googleのメールサービスの権限は不要。

Script Propertiesの既存値は変更しません。旧Config.gsの重複ヘルパーを戻さないでください。`initializeCommunityMessaging` は既存の8つの非公開シートのヘッダー末尾に必要な列（2026-10-21は `Community Replies` と `Community Participants` の `access_revoked_at`）だけを追加し、番号と内部pepperを準備します。既存行の削除やテーブルの作り直しはしません。未確認・未承認の旧返信を自動で公開しません。

**Deploy → Manage deployments → Edit → New version** で既存Webアプリを更新します。公開状態APIに `messaging_version:2026-10-23.1`、`inline_replies:true`、`instant_publish:true`、`persistent_links:true` があることを確認します。サイトと旧API、旧サイトと新APIのどちらの組み合わせでも会話は開けます（旧APIの間はリンクが1時間で失効します）。古いAPIの場合はフォームを停止し、旧メール転送へ戻しません。

非公開シートやScript Propertiesを公開JSONへ追加しません。静的同期は `CM_PUBLIC_DIRTY` を既存5分トリガーで処理し、通常の定期同期も維持します。公開詳細の既存noindex方針を維持し、会話ページには解析・シェアスクリプトを読み込みません。

## 検証

会話画面では送信中・成功・失敗を入力欄のすぐ下に表示し、通信中は本文の編集と再送を止めます。保存後の再読込だけに失敗した場合は「送信済み」を明示します。通信失敗後に同じ本文を再送すると同じrequest_idを使い、本文を変えた場合は新しいrequest_idを使います。

参加者の説明は両側から読める文言にし、公開返信・非公開会話の日時は閲覧端末にかかわらずEurope/Berlin（夏時間対応）で表示します。会話の表示中は1分ごとに新着を確認し、非表示タブ・送信処理中・取得中は追加の取得を止めます。過去の履歴を読んでいる場合は位置を保ち、新着ボタンから末尾へ移動できます。取得の失敗でも履歴と入力中の本文を保持し、端末で閉じた後に遅い応答が返っても会話を再表示しません。

通知メールの送信に失敗した場合は、次の5分トリガーから5分・10分・20分…と間隔を倍にして（最長1日）再送します。失敗時はZohoのエラーコードと説明だけをログに残し、宛先や本文は記録しません。投稿完了メールも管理用リンクの `&token=` を保つためテキスト形式で送ります。投稿完了メールの送信に失敗した場合も通知キューに登録し、同じ間隔で再送します（キューには管理用リンクを保存せず、送信時に投稿行から組み立てます。投稿行にリンクがない場合は新しい管理トークンを発行して照合値を置き換えます）。

自動通知（会話・投稿完了）は、Zohoの送信ブロック（`550 5.4.6 Unusual sending activity detected`）を避けるため、外部あてを1分4通・1時間15通までに制限します。上限を超えた分は失敗扱いにせず、5分後の自動処理で送ります。サイト自身のドメインあて（運営通知）や、問い合わせ・求人など他のメールは制限しません。

通知本文を文字列で組み立てたメールはZohoへ `mailFormat: plaintext` で送信します。実メールのテキスト版でURLの `&id=` が `&amp;id=` に変換される不具合を確認したためです。明示的な `html` / `htmlBody` があるメールだけ従来のHTML形式を使います。受信した生MIMEでも、リンクのクエリとフラグメントが元のまま届くことを確認します。

`node scripts/test-community-messaging.mjs`、`npm run validate`、ブラウザーテストで、旧スキーマ移行、全カテゴリの即時公開、固定番号・返信先・削除済み表示、パスワード照合、メール以外の初回セッション、クロス投稿の拒否、セッション隔離、再送の重複防止、通知再試行、モバイル表示を確認します。

本番では最新APIの対応状態、元の公開投稿の取得、認証なしでの会話アクセス拒否、詳細ページのフォームを確認します。運営管理の2つのテスト受信箱での実配信・往復も確認対象ですが、許可なしに既存の投稿者へテスト通知を送りません。

ロールバックではまずフォームを停止し、旧バージョンのGASとサイトに戻します。新規の `published` 返信と追加列は旧コードから見えない場合があるため、旧ヘッダー前提のコードをそのまま使わず互換性を確認してください。旧submitInquiryのメール転送は再有効化しません。
